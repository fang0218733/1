# 人工需求确认与交付版本

## 当前状态

已提供原生微信客户流程、电脑网页后台、Node.js24服务及SQLite持久数据库。当前默认是本地模拟，尚未替你注册小程序、开通服务器、配置正式身份或上线。模拟管理员操作只在本机；自动化测试中的身份服务是替身，不能证明真实微信登录已连通。

不提供微信支付、赞赏码展示、外部付款跳转或支付密码/银行卡采集。人工收款仅是预留的管理员核实工作流：页面不会自行收钱，“已核实收款”也不触发资金支付；“记录退款”只登记已经实际核实的全额退款，不执行资金退款。不得把固定套餐费包装为自愿赞赏。

## 三档与需求单

基础套餐为50题、100题、私人定制，另增48.8元150题高级版；私人采用完整100题精细问卷且始终不公开。三档独立价格在`miniprogram/data/config.js`及后台价格配置维护，不再用倍率推导私人价格。配置为null显示“价格待确认”，可在后台清空价格恢复待确认。50题12.8元和100题18.8元沿用已确认价格；私人价格未确定。不引入新的虚构报价。

提交生成“待确认需求单”，初始付款“待确认”、制作“待处理”。客户可复制唯一编号、套餐、题库版本、题目与全部答案、创建时间、报价快照用于私聊核对。报价快照冻结提交时价格，后台新价格不回写既有需求单。管理员与客户私聊确定的金额、交付时间、修改次数及退款条件另行保存。注意不要将客户复制的需求单转发至公开大厅。

付款状态：待确认 → 管理员确认报价后待付款 → 管理员实际核实后已人工核实 → 如实际全额退款则已退款。
制作状态：待处理 → 制作中 → 已交付，或管理员取消后已取消。付款与制作独立存储，取消制作不会自动假称退款。历史订单缺乏新状态时显示“历史待核对”，不得自动推断已付款；该版本不自动迁移旧版支付/会员记录。

## 本机运行与后台操作

从仓库根目录：

```sh
npm run check
npm test
npm run server:demo
```

第三条跨平台启动仅本机演示。浏览器访问你自己电脑的本机8080端口`/admin`，演示登录不填密码。创建角色卡或需求单状态均为模拟，不应作为真实收款凭证。小程序连接同一后台需在`runtime.js`填写服务地址；本机开发工具可联调，但正式版必须使用已配置合法域名的HTTPS地址。

后台定制需求：选择需求单 → 查看完整答案和版本 → 录入报价/北京时间交付日期/修改次数/退款条件 → 保存双方约定 → 实际核实收到约定款后点击核实收款 → 开始制作 → 粘贴或上传TXT（50KB内、每章最多8000字）→ 确认交付。客户只能查询自己的需求单并复制已交付成品。私人订单服务端禁止公开。普通订单公开须客户明确选择“公开到免费大厅”，公开内容不得包含问卷中的私人资料。

正式后台必须使用至少16位随机密码，HTTPS安全Cookie会话及来源校验；客户令牌不能充当管理员会话。改价、核实收款、记录退款和交付均由服务端验证权限及订单修订号，并保存操作记录。模拟模式仅绑定127.0.0.1，禁止公网运行。

## 正式部署准备

1. 在微信官方平台注册小程序并核实个人主体的服务类目、虚构角色定制服务及平台对经营活动的要求；完成适用备案、隐私说明和审核。
2. 确认人工收款、私聊沟通和拟采用收款方式是否符合微信与支付平台规则。赞赏码尚未获确认，不直接展示或接入。营业额较小不等于允许用赞赏码收取固定套餐费用；人工核实界面存在也不证明某收款方式获准。
3. 准备HTTPS域名及持久化服务器，单实例Node.js24。安全配置`DEMO_MODE=false`、`PUBLIC_ORIGIN`、`ADMIN_PASSWORD`、`WECHAT_APP_ID`、`WECHAT_APP_SECRET`、`DATA_DIR`和`MEDIA_DIR`。AppSecret只能在服务端，不提交仓库、不发聊天。人工制作不需要DeepSeek密钥。
4. 配置请求/图片下载合法域名，将小程序`runtime.js`服务地址设为真实HTTPS域名。`npm run deploy:check`只检查配置存在，不替代账号与网络验证。
5. 使用两个真实微信账号验证互相不能查看对方需求单，用管理员账号验证改价和状态操作；核对金额、时间、修改和退款条件后，再开放试运营。
6. 正式沟通入口、隐私说明中的运营联系信息、制作服务规则及人工收款方式须由运营者确定。本次没有虚构微信号、客服电话或退款承诺。

备份工具和部署示例沿用`server/backup.cjs`、Dockerfile与systemd示例；默认布局一致性停机备份与恢复步骤见原部署说明的备份章节。数据库包含客户需求，应限制访问并制定保存/删除期限。不能把无持久磁盘的实例当成持久后台。

## 后续正式支付接口

`server/payment.cjs`是可替换付款边界。本阶段只允许经管理员鉴权的人工核实和退款记录。正式渠道通知入口未启用，不能通过提交“已付款”或verified字段伪造付款。

未来适配微信支付时应增加正规服务端下单与回调：先核验签名、解密通知并核对商户、订单号、币种、金额和成功状态，才更新支付记录；以交易号幂等处理重复通知。退款同样需真实渠道结果核验。不得仅修改界面状态或环境开关声称正式支付已接通。当前会员和邀请返款不因人工收款标记自动发放权益。

## 验证范围

`npm run check`和`npm test`覆盖三档题库、草稿、报价待确认、提交快照与幂等、订单归属、客户伪造付款无效、管理员登录权限、报价/收款/制作/交付/全额退款、修订冲突、私人禁止公开及备份恢复。

微信开发者工具编译、真机存储与剪贴板、正式微信登录、私聊核对操作、TXT上传的真实浏览器表现、HTTPS部署和平台规则仍需人工验收；未验证的正式能力不得宣传为上线完成。

## yu伴品牌、支付凭证与邀请核对

客户在“我的需求单”进入“提交/更新支付凭证”，可上传一张2MB以内PNG/JPEG/WebP截图或300字核对说明。请裁剪为本单必要金额与时间，遮盖账号、银行卡、余额等信息；不采集密码。凭证提交不会改变付款状态。已核实/已退款/已取消订单不再接受替换凭证。服务器按需求单归属校验，凭证存在私有数据库，不作为公开封面或大厅文件发布；公开订单接口仅返回提交时间及待核对标记，管理员需登录才能读取图片正文。当前没有自动图片脱敏识别，运营者仍需控制访问、保留期限与删除流程。

后台“定制订单”上方的“邀请核对记录”按邀请码显示：绑定人数、管理员已核实收款人数、正式渠道核验人数，以及匿名客户标识和对应需求单号。点开相关需求单，查凭证并对照实际到账后人工核实；同一客户在汇总中只计一次，已退款不计人工核实人数。客户在“专属定制→我的邀请记录”可分享带码的小程序卡片并查看自己的汇总，不获得其他客户的凭证或答案。

目前人工核实统计只是核对线索，不自动占用“三人返一单”的正式活动资格，也不执行退款。若要在人工收款阶段兑现活动，需逐单核实有效付款、记录邀请是否已用于返款及实际退款结果；现阶段正式渠道实付款统计仍为0。达到3个绑定或上传3张截图，均不能当作3位有效实付款客户。小程序与后台必须部署并连接同一服务才有跨设备统计；本地模拟没有真实邀请关系或真实管理员同步。

## 成品公开选择（最新版）

50题和100题提交前必须显式选择“公开到免费大厅”或“仅自己可见”，初始无默认选择。不公开不改变普通套餐及价格；私人定制固定不公开。选择随草稿保存，提交时保存公开范围、授权版本及时间。最终确认弹窗再次说明公开范围，需求单和管理员页面均展示该选择。提交需求、付款或凭证上传都不构成额外公开授权。

成品仅在人工核实收款后由管理员制作交付。公开选择只是允许公开，不自动发布；管理员交付时仍需主动选择发布。只公开审核后的成品与展示信息，不公开问卷、具体要求、支付凭证或客户身份。选择仅自己可见以及历史缺少新版明确授权的订单，后台禁用发布，服务端同样拒绝绕过。

已提交选择作为订单授权快照保留，当前未实现客户自助变更已提交授权；客户提出撤回时由管理员核对并下架公开卡。未部署期间仅本机模拟，客户选择公开不会自行同步到你的电脑；部署并连接同一后台后，管理员发布的成品才会在大厅即时读取，无需为每张卡上传小程序代码。

真机验收：普通套餐未选不可提交；选择不公开仍按原套餐价；草稿选择恢复；私人固定不公开；确认弹窗和订单范围一致；管理员交付仅自己可见订单不能发布；已授权公开订单在审核发布后出现于大厅。此次仅完成公开选择，线上部署仍待官方云资源与身份配置。

## 分层交付文件包与48.8元高级分支版

当前套餐：50题12.8元、100题18.8元、150题世界线高级定制48.8元；私人定制保留100题精细内容、不公开，独立价格尚未设置时显示待确认，不推导虚构金额。

- 50题基础包：人物设定、性格与表达方式、互动规则与边界、开场与对话示例，共4章。
- 100题精细包：基础4章，加人物经历/成长时间线、关系发展、可持续剧情支线、导入使用说明，共8章。
- 高级包：精细8章，加世界观/运行规则、世界背景/社会环境、世界线/剧情节点，共11章。
- 私人包采用精细8章，固定不公开。

每个ZIP含完整整合稿、分章TXT、交付说明及带SHA256的文件清单，基础7个文件、精细11个文件、高级14个文件。章节数体现交付范围，不代表自动生成质量承诺；管理员必须实际撰写并审核各章。客户问卷、具体要求、付款凭证和账号信息不打包进成品。

高级题库由`advanced-themes.js`定义50个主题，每个主题连续3题。第一题选方向，第二题的具体菜单随第一题变化，第三题围绕第二题选定场景继续细化，共150题。修改第一题会清除该主题的第二、三题，修改第二题清除第三题，不影响其他主题。跳过与跳过剩余仍支持“由设计师决定”；服务端按答案重建路径校验，拒绝保留旧分支答案。提交冻结实际走过的题目文本和`advanced-branch-150-v1`版本。

后台订单审核逐项录入必填章节；缺任何必填章不能交付，收款与公开授权规则继续生效。管理员可先在TXT编辑器完成内容，分别粘贴进对应章节；当前TXT上传入口导入人物设定章，其他章单独录入。ZIP由服务器从审核后的章节生成，不接受来源不明压缩包的自动解压。

客户在已交付需求单点击“下载/导出完整交付ZIP文件包”，通过身份令牌下载并分享文件，在电脑/支持ZIP的工具解压使用。只能下载本人已交付包，未交付和其他客户均拒绝。正式版本需将服务HTTPS域名配置为微信request和downloadFile合法域名，并在真机验证文件分享能力；本地模拟没有真实交付包，不声称已完成服务端交付。

本次完成代码与本地服务验证，仍未部署线上后台。将服务器部署并连接体验版后，才能实际收到客户问卷、按章制作和交付。修改功能代码仍需重新上传体验版；接通后台后新增成品和发布公开文件内容不必重新上传小程序代码。

## 四张大厅人物卡完整规格

原三张示例扩为独立的完整双人物设定：林知秋与许栀（BG）、周予晴与顾映澄（GL）、沈时安与叶闻溪（BG）。每张约4300字，包含双方背景与成长、性格明暗面、职业与生活、关系张力、世界背景、配角、执行规则、对话示例及两个开场。裴砚声与姜知宜保持BG，上传定稿原文保留，追加主控选择说明。

四张均可自行选择主控人物，模型扮另一位，不代写用户主控人物的台词或决定；交换主控不自动更改配对方向。BG/GL是卡片配对标签，不通过当前主控人物性别判断。

更新会升级已有的短版默认卡，纠正裴卡的旧BL标签并添加使用说明，保留收藏、下载及下架状态。管理员自行改写的其他稿件不会被默认稿覆盖；服务端升级前记录`catalogBackups`，仅内部保存，不作为公开大厅项目。尚未部署的体验版仍需下载新版代码重新上传；已有服务端部署须更新服务代码并重启才能应用目录升级。

## 固定人物代入入口（覆盖此前自由主控说明）

大厅四对人物拆成8张固定视角卡：林知秋/许栀、周予晴/顾映澄、沈时安/叶闻溪、裴砚声/姜知宜。每张以所代入人物命名，明确用户是故事中该人物，模型扮其对方，不添加第三位恋爱人物。共用同一条故事主线，但角色控制说明按固定视角调整，不在公开卡中提供交换主控。原成对稿作为源资料保留，不继续出现在客户大厅。

主页BG/GL/BL下新增“全部视角 / 代入男主 / 代入女主”。BG有3个男主和3个女主入口；GL有2个女主入口。选择GL再选男主暂无匹配，不虚构男性角色。角色性别视角与配对标签独立，用户可以分别使用分类、收藏和搜索。

旧成对卡退到隐藏状态并保留服务端备份；对应收藏只迁移一次到两个新入口。旧下载记录保留，不将一次旧下载重复计成两个新卡下载。新卡下载重新统计，避免虚构热度。真机需验证新增筛选、固定身份提示、复制/下载正文和旧缓存迁移；代码更新仍需上传体验版，部署后台后还需更新服务代码。

## 独立角色与自由用户形象（覆盖固定代入版）

首页筛选改为“选择男性角色 / 选择女性角色”，按模型扮演的角色性别筛选。卡片标题就是所选角色，例如选择裴砚声，则模型扮演裴砚声；用户以自己塑造的形象取代原故事另一方的位置，不是扮演姜知宜，也不是插入原配之间的第三个人。

八张单角色卡各自保留所选人物的身份、性格和成长档案，共同世界与关系主线保留；原另一方的个人档案不作为用户设定，引用位置用`{{user}}`表示。用户姓名、外貌、职业、性格、经历和表达由用户自己塑造，未提供项保持开放。每位角色的新开场只描写该角色的行为，给用户自己的回应空间，不预写用户动作或同意。BG/GL分类保持原关系方向，角色性别不再表示用户必须扮演某个原作人物。

已缓存的固定代入默认稿升级为新版；下架状态、封面、收藏和下载记录保留。后台自定义稿仍不被默认稿盲目覆盖。原成对定稿保留在源资料模块，不作为客户端完整双人代入卡展示。
