# 人工需求确认与交付版本

## 当前状态

已提供原生微信客户流程、电脑网页后台、Node.js24服务及SQLite持久数据库。当前默认是本地模拟，尚未替你注册小程序、开通服务器、配置正式身份或上线。模拟管理员操作只在本机；自动化测试中的身份服务是替身，不能证明真实微信登录已连通。

不提供微信支付、赞赏码展示、外部付款跳转或支付密码/银行卡采集。人工收款仅是预留的管理员核实工作流：页面不会自行收钱，“已核实收款”也不触发资金支付；“记录退款”只登记已经实际核实的全额退款，不执行资金退款。不得把固定套餐费包装为自愿赞赏。

## 三档与需求单

三套餐为50题、100题、私人定制；私人采用完整100题精细问卷且始终不公开。三档独立价格在`miniprogram/data/config.js`及后台价格配置维护，不再用倍率推导私人价格。配置为null显示“价格待确认”，可在后台清空价格恢复待确认。50题12.8元和100题18.8元沿用已确认价格；私人价格未确定。不引入新的虚构报价。

提交生成“待确认需求单”，初始付款“待确认”、制作“待处理”。客户可复制唯一编号、套餐、题库版本、题目与全部答案、创建时间、报价快照用于私聊核对。报价快照冻结提交时价格，后台新价格不回写既有需求单。管理员与客户私聊确定的金额、交付时间、修改次数及退款条件另行保存。注意不要将客户复制的需求单转发至公开大厅。

付款状态：待确认 → 管理员确认报价后待付款 → 管理员实际核实后已人工核实 → 如实际全额退款则已退款。
制作状态：待处理 → 制作中 → 已交付，或管理员取消后已取消。付款与制作独立存储，取消制作不会自动假称退款。历史订单缺乏新状态时显示“历史待核对”，不得自动推断已付款；该版本不自动迁移旧版支付/会员记录。

## 本机运行与后台操作

从仓库根目录：

```sh
npm run check
npm test
npm run server:demo
```

第三条跨平台启动仅本机演示。浏览器访问你自己电脑的本机8080端口`/admin`，演示登录不填密码。创建角色卡或需求单状态均为模拟，不应作为真实收款凭证。小程序连接同一后台需在`runtime.js`填写服务地址；本机开发工具可联调，但正式版必须使用已配置合法域名的HTTPS地址。

后台定制需求：选择需求单 → 查看完整答案和版本 → 录入报价/北京时间交付日期/修改次数/退款条件 → 保存双方约定 → 实际核实收到约定款后点击核实收款 → 开始制作 → 粘贴或上传TXT（50KB内、文字最多12000字）→ 确认交付。客户只能查询自己的需求单并复制已交付成品。私人订单服务端禁止公开。普通订单公开仍需已保存的客户告知确认，公开内容不得包含问卷中的私人资料。

正式后台必须使用至少16位随机密码，HTTPS安全Cookie会话及来源校验；客户令牌不能充当管理员会话。改价、核实收款、记录退款和交付均由服务端验证权限及订单修订号，并保存操作记录。模拟模式仅绑定127.0.0.1，禁止公网运行。

## 正式部署准备

1. 在微信官方平台注册小程序并核实个人主体的服务类目、虚构角色定制服务及平台对经营活动的要求；完成适用备案、隐私说明和审核。
2. 确认人工收款、私聊沟通和拟采用收款方式是否符合微信与支付平台规则。赞赏码尚未获确认，不直接展示或接入。营业额较小不等于允许用赞赏码收取固定套餐费用；人工核实界面存在也不证明某收款方式获准。
3. 准备HTTPS域名及持久化服务器，单实例Node.js24。安全配置`DEMO_MODE=false`、`PUBLIC_ORIGIN`、`ADMIN_PASSWORD`、`WECHAT_APP_ID`、`WECHAT_APP_SECRET`、`DATA_DIR`和`MEDIA_DIR`。AppSecret只能在服务端，不提交仓库、不发聊天。人工制作不需要DeepSeek密钥。
4. 配置请求/图片下载合法域名，将小程序`runtime.js`服务地址设为真实HTTPS域名。`npm run deploy:check`只检查配置存在，不替代账号与网络验证。
5. 使用两个真实微信账号验证互相不能查看对方需求单，用管理员账号验证改价和状态操作；核对金额、时间、修改和退款条件后，再开放试运营。
6. 正式沟通入口、隐私说明中的运营联系信息、制作服务规则及人工收款方式须由运营者确定。本次没有虚构微信号、客服电话或退款承诺。

备份工具和部署示例沿用`server/backup.cjs`、Dockerfile与systemd示例；默认布局一致性停机备份与恢复步骤见原部署说明的备份章节。数据库包含客户需求，应限制访问并制定保存/删除期限。不能把无持久磁盘的实例当成持久后台。

## 后续正式支付接口

`server/payment.cjs`是可替换付款边界。本阶段只允许经管理员鉴权的人工核实和退款记录。正式渠道通知入口未启用，不能通过提交“已付款”或verified字段伪造付款。

未来适配微信支付时应增加正规服务端下单与回调：先核验签名、解密通知并核对商户、订单号、币种、金额和成功状态，才更新支付记录；以交易号幂等处理重复通知。退款同样需真实渠道结果核验。不得仅修改界面状态或环境开关声称正式支付已接通。当前会员和邀请返款不因人工收款标记自动发放权益。

## 验证范围

`npm run check`和`npm test`覆盖三档题库、草稿、报价待确认、提交快照与幂等、订单归属、客户伪造付款无效、管理员登录权限、报价/收款/制作/交付/全额退款、修订冲突、私人禁止公开及备份恢复。

微信开发者工具编译、真机存储与剪贴板、正式微信登录、私聊核对操作、TXT上传的真实浏览器表现、HTTPS部署和平台规则仍需人工验收；未验证的正式能力不得宣传为上线完成。
